# 支付宝沙箱集成流程文档

支付宝沙箱是开放平台提供给开发者的、与生产环境完全隔离的联调环境。它的最大价值不是"能付款"，而是**让你在没签约、没资质、没真实资金的情况下，把支付链路完整跑通**：下单、收银台、付款、异步通知、查询、退款全部可以本地闭环验证。

但沙箱不等于生产。落地时真正容易卡住的只有三件事：**网关和 APPID 是否指向同一套环境**、**密钥格式与签名模式是否匹配**、**异步通知地址是否真的能被外网访问**。本文按"划边界 → 拿配置 → 写代码 → 本地联调 → 排错 → 切生产"的顺序展开，代码以 Hono \+ TypeScript 为例。

# 沙箱能替代什么、不能替代什么

先把预期校准好，可以省掉大量无效排查。沙箱的接口逻辑大体与生产一致，但会自动跳过或放宽一些业务门槛（例如无需等待产品签约即可调用接口），因此它是一套可用的独立测试环境，而不是生产环境的镜像。

|能做到|做不到 / 不能依赖|
|---|---|
|- 不签约直接调用支付、查询、退款、关单接口<br>- 用虚拟买家账号完成扫码、登录、输密码的真实交互<br>- 接收并调试异步通知，验证自己的验签与幂等逻辑<br>- 反复重放订单和异常分支，不产生任何真实资金|- 不能替代生产验收，上线前仍须在正式环境跑通小额真实交易<br>- 沙箱数据（用户 ID、交易号、订单）与生产完全隔离，**禁止混用**<br>- 对账单等部分接口只返回模板数据，没有真实对账内容<br>- 少数营销、资金、理财类能力在沙箱不支持，以官方接口支持列表为准|

# 开通与环境信息获取

准备阶段的目标只有一个：把后面写代码需要的几样东西一次拿全。按顺序执行。

1. **登录支付宝开放平台**。企业或个人开发者账号均可，沙箱不需要额外资质审核。

2. **进入沙箱控制台**，地址 [https://open\.alipay\.com/develop/sandbox/app](https://open.alipay.com/develop/sandbox/app)。平台会为每个开发者**自动创建一个沙箱应用**，无需手动新建。

3. **记录沙箱 APPID 与网关**。APPID 在应用信息区直接可见；网关必须使用 **https://openapi\-sandbox\.dl\.alipaydev\.com/gateway\.do**。若看到的地址不带 **\-sandbox\.dl**，说明账号仍是老沙箱，需在控制台右上角点击"升级沙箱环境"。

4. **确认接口加签方式**。默认是"系统默认密钥"，也可切换"自定义密钥"；两种模式下平台都会给出可用的应用私钥与支付宝公钥，直接复制即可。

5. **获取买家测试账号**。在沙箱账号页面可以拿到平台分配的**买家账号、登录密码、支付密码**及虚拟余额，这类账号只能用于沙箱付款。

6. **下载沙箱版支付宝客户端**。正式版客户端无法支付沙箱订单，必须使用控制台提供的沙箱版客户端，具体入口以控制台当前展示为准。

准备好后把下列信息落到环境变量或密钥管理里，代码中不要再出现硬编码：**沙箱 APPID**、**沙箱网关**、**应用私钥**、**支付宝公钥**、**买家测试账号**，以及后续要用的**公网回调域名**。

# 密钥与签名配置

沙箱提供三种密钥模式。本地联调优先用前两种，证书模式留到接近生产时再验证。

|模式|配置方式|适用与代价|
|---|---|---|
|**系统默认密钥**|平台自动生成密钥对，控制台直接给出应用私钥和支付宝公钥，复制即可用。|跑通沙箱最快的方式。缺点是无法验证"自行生成密钥并上传公钥"这一生产必经步骤。|
|**自定义密钥**|用开放平台密钥工具生成 RSA2 密钥对，把**应用公钥**上传到沙箱应用，私钥留在服务端，控制台回显**支付宝公钥**。|与生产配置路径一致，推荐联调中期切换。上传后需确认公钥已生效，否则请求报签名错误。|
|**证书模式**|需要应用公钥证书、支付宝公钥证书、支付宝根证书三份文件，配合应用私钥。|仅建议在准备切生产时验证一次，本地开发用前两种足够。|

签名环节有四个高频坑，逐条确认能省掉大半调试时间：

- **私钥格式**：RSA2 建议使用 **PKCS8**（以 BEGIN PRIVATE KEY 开头）。若工具导出的是 PKCS1（BEGIN RSA PRIVATE KEY），需转换格式或把 SDK 的密钥类型配置对齐。

- **公钥与私钥不能错位**：加签用**应用私钥**，验签用**支付宝公钥**。把应用公钥当成支付宝公钥，是最常见的验签失败原因。

- **密钥内容不要截断**：复制时容易丢掉首尾标识行或末尾换行，SDK 会直接抛签名异常。

- **加签方式与代码一致**：控制台选公钥模式就用公私钥，选证书模式就配三份证书路径，两者不能混搭。

# 服务端接入

下面四段代码构成一个最小闭环：初始化客户端、发起支付、处理异步通知、主动查询与关单。示例使用官方 **alipay\-sdk**；若换用其他 HTTP 封装，签名规则不变。

## 客户端初始化

把沙箱与生产的差异全部收敛到环境变量，代码本身在切换环境时不需要改动。

```ts
import { AlipaySdk } from 'alipay-sdk'
import { env } from './env' // zod 校验过的环境变量

export const alipay = new AlipaySdk({
  appId: env.ALIPAY_APP_ID,                 // 沙箱 APPID
  privateKey: env.ALIPAY_PRIVATE_KEY,       // 应用私钥，PKCS8，含首尾标识行
  alipayPublicKey: env.ALIPAY_PUBLIC_KEY,   // 支付宝公钥，仅用于验签
  gateway: env.ALIPAY_GATEWAY,              // 沙箱：https://openapi-sandbox.dl.alipaydev.com/gateway.do
  signType: 'RSA2',
  keyType: 'PKCS8',
  timeout: 10000,
})
```

## 发起支付

电脑网站支付返回一段可直接跳转的 URL；手机网站支付同理，换成 **alipay\.trade\.wap\.pay** 与 **QUICK\_WAP\_WAY**。关键是**先落库再下单**，并让本地关单时间与支付超时时间对齐。

```ts
app.post('/api/pay/create', async (c) => {
  const { orderId, amount, subject } = await c.req.json()

  // 1. 先落库：status = pending，记录 expire_at
  // 2. 再向 BullMQ 投一个延迟任务，到期自动关单，jobId 回写订单表
  // 3. 最后才向支付宝下单
  const payUrl = alipay.pageExec('alipay.trade.page.pay', {
    method: 'GET',
    bizContent: {
      out_trade_no: orderId,
      total_amount: amount,                 // 单位：元，字符串，两位小数，如 '0.01'
      product_code: 'FAST_INSTANT_TRADE_PAY',
      subject,
      timeout_express: '30m',               // 与本地关单时间保持一致
    },
    returnUrl: env.PUBLIC_BASE_URL + '/pay/result',      // 同步跳转，仅供展示
    notifyUrl: env.PUBLIC_BASE_URL + '/api/pay/notify',  // 异步通知，状态变更的唯一依据
  })

  return c.json({ payUrl })
})
```

|参数|要点|
|---|---|
|**out\_trade\_no**|商户侧唯一订单号。同一笔订单重复下单会返回重复交易错误，可用来做天然幂等。|
|**total\_amount**|单位为元，**字符串**，最多两位小数。传数字类型或带多余精度会直接报参数错误。|
|**timeout\_express**|支付宝侧最长等待付款时间。必须与本地延迟关单时间一致，否则会出现"支付宝已关闭、本地仍待付款"。|
|**notify\_url**|必须公网可达、返回纯文本 **success**。它是状态变更的唯一可信来源，同步 return\_url 只负责页面跳转。|

## 处理异步通知

异步通知是 **application/x\-www\-form\-urlencoded** 的 POST 请求。处理顺序固定为：验签 → 判断交易状态 → 幂等校验 → 金额比对 → 改单 → 返回 success。

```ts
app.post('/api/pay/notify', async (c) => {
  const body = (await c.req.parseBody()) as Record<string, string>

  // 1. 验签失败一律拒绝，不要继续读业务字段
  if (!alipay.checkNotifySign(body)) {
    return c.text('failure', 400)
  }

  const { out_trade_no, trade_status, total_amount } = body

  if (trade_status === 'TRADE_SUCCESS' || trade_status === 'TRADE_FINISHED') {
    // 2. 幂等：只有本地仍是 pending 才处理，重复通知直接跳过
    // 3. 校验 total_amount 与本地订单金额一致，防止参数被篡改
    // 4. 更新为 paid，并取消 BullMQ 中对应的超时关单任务
  }

  // 5. 必须是纯文本 success，否则支付宝会按策略多次重试
  return c.text('success')
})
```

三个必须遵守的细节：**返回体只能是 success**，带 HTML、JSON 或多余空格都可能被判定为处理失败；**不要依赖通知到达次数**，支付宝在未收到 success 时会按固定间隔重投（约 25 小时内 8 次），因此幂等是硬要求；**验签只认支付宝公钥**，参与验签的字段是除 sign 与 sign\_type 之外的全部参数。

## 主动查询与关单

异步通知可能因网络或内网穿透中断而丢失，本地必须有兜底：延迟任务到点时先查支付宝侧真实状态，再决定关单还是补单。

```ts
// 查单：以支付宝侧状态为准
const res = await alipay.exec('alipay.trade.query', {
  bizContent: { out_trade_no: orderId },
})
// res.tradeStatus === 'TRADE_SUCCESS' 说明用户其实已付款，应补单而不是关单

// 关单：仅在确认未付款时调用
await alipay.exec('alipay.trade.close', {
  bizContent: { out_trade_no: orderId },
})
```

这样本地关单逻辑就变成"**先查一次，已付款则补单、未付款则关单**"，配合 BullMQ 延迟任务即可覆盖通知丢失的极端情况。

# 本地联调

联调的前置条件是**回调地址能从公网访问**。支付宝服务器访问不到 localhost，所以本地开发必须用内网穿透把 **/api/pay/notify** 暴露出去，再把穿透域名写进 **PUBLIC\_BASE\_URL**。完整测试顺序如下。

1. 启动服务，先用 curl 打一次穿透域名下的 **/api/pay/notify**，确认没有被网关、鉴权中间件或 CSRF 校验拦在外层。

2. 调用下单接口拿到 payUrl，在浏览器打开，确认能进入沙箱收银台，且金额与商品标题正确。

3. 用**沙箱买家账号**在**沙箱版客户端**完成付款，付款成功后先不关页面，留作排查证据。

4. 看服务端日志：是否收到异步通知、验签是否通过、订单是否变为 paid、延迟关单任务是否已取消。

5. 再测异常分支：下单不付款等到超时，确认延迟任务查单后完成关单；重复投递通知，确认幂等生效；篡改金额后再通知，确认金额比对拦截。

|交易状态|含义与本地动作|
|---|---|
|**WAIT\_BUYER\_PAY**|交易已创建，等待付款。本地保持 pending，不要改单。|
|**TRADE\_SUCCESS**|已付款。本地改为 paid，取消超时关单，进入履约流程。|
|**TRADE\_FINISHED**|交易结束且不可退款。与付款成功同等处理，同样需要幂等。|
|**TRADE\_CLOSED**|未付款超时关闭或全额退款。本地置为 closed / refunded，注意区分两种成因。|

# 常见问题排查

沙箱联调里绝大多数问题集中在下面几种，按"先查环境、再查密钥、最后查网络"的顺序排查即可。

|现象|常见原因|处理|
|---|---|---|
|**invalid\-app\-id**|用正式 APPID 连沙箱网关，或仍在用老沙箱网关地址。|确认 APPID 与网关来自同一套环境；老账号按控制台提示升级沙箱。|
|**invalid\-signature**|私钥不是当前应用配置的那把；私钥格式与配置不符；密钥被截断。|重新对齐控制台公钥与本地私钥；检查首尾标识行与换行；必要时用密钥工具重新生成一对。|
|**扫码提示"调试错误"**|用正式版支付宝客户端扫了沙箱订单。|改用控制台提供的沙箱版客户端，并登录沙箱买家账号。|
|**收不到异步通知**|notify\_url 不是公网地址、穿透域名失效、被网关或鉴权中间件拦截。|用 curl 从外网验证可达性；确认 notify\_url 为 https 且无 CSP、WAF 拦截；检查应用是否处理了 form 请求。|
|**通知一直重投**|返回体不是纯文本 success，或处理逻辑抛异常返回了 500。|成功路径只 **c\.text\('success'\)**；业务异常也要先落日志再返回 success 还是 failure，按幂等能否承受来决定。|
|**参数错误 / 金额异常**|total\_amount 传了数字、超过两位小数，或 subject 含特殊字符。|统一用字符串并保留两位小数；subject 做长度与字符校验。|

# 切换生产检查清单

沙箱跑通不等于可以上线。切生产本质是一次**配置替换**，逐项核对能避免把测试配置带上去。下面三列对照覆盖了所有需要改动的配置项。

|配置项|沙箱|生产|
|---|---|---|
|**网关**|https://openapi\-sandbox\.dl\.alipaydev\.com/gateway\.do|https://openapi\.alipay\.com/gateway\.do|
|**APPID**|沙箱应用 APPID|正式应用 APPID|
|**应用私钥**|沙箱密钥对中的应用私钥|正式应用的应用私钥（证书模式下为私钥文件）|
|**支付宝公钥**|沙箱环境回显的支付宝公钥|正式环境的支付宝公钥 / 支付宝公钥证书|
|**notify\_url**|内网穿透临时域名|正式 https 域名，且已完成备案与可访问性验证|
|**付款账号**|沙箱买家账号 \+ 沙箱版客户端|真实用户 \+ 正式支付宝客户端|

上线前还需要逐条确认的事项：

- **产品已签约**：沙箱能调用不代表生产已开通，正式环境的支付产品需要完成签约与审核。

- **证书与密钥已上传生效**：证书模式下漏传根证书，会出现签名通过但验签失败。

- **异步通知幂等与金额校验已上线**：这两条是生产环境唯一能防止重复改单与金额篡改的防线。

- **真实小额验收已完成**：在正式环境跑一笔最小金额真实交易，覆盖下单、付款、通知、查询、退款全链路。

- **告警已挂上**：通知未达、验签失败、金额不一致、关单异常都应进监控或日志告警，不要只靠人看日志。

- **沙箱配置已彻底清除**：确认环境变量、数据库里的测试订单与穿透域名都没有残留。
